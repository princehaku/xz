| 问题与触发条件 | 修复结果 |

| 预览在共享 ESP timer 任务等待取帧，拍照 HTTP 占用应用主循环 | 预览和按钮拍照移至独立相机任务，最高约 10 FPS；系统定时器和应用循环可继续处理事件 |

| JPEG 队列多余复制、异常路径阻塞或空等，上传写入结果未检查 | 直接接收编码器的 JPEG 缓冲；4 KB 分块上传，检查失败，限制识图响应最多 64 KB |

| 每个 TTS stop 创建等待任务，旧完成任务清空新播报；中途打断后停在 Speaking | 使用单一定时事件与会话代次；重复 stop 幂等，打断后正确切换状态 |
| 仅队列为空就判定播完，忽略正在解码、写入 I2S 的帧；清队列后旧在途帧重新入队 | 计入在途帧和 200 ms 尾音时间，编解码代次取消旧结果 |
| 拍照等待 TTS 时打开麦克风、复用失败的待发文本；无 AEC 时仍在播报期间上行 | 拍照走文本请求且保持关麦，失败不保留待发文本；无 AEC 时抑制播报回声上行 |
| 主循环一次无限制发送音频、编码每帧额外分配和复制 | 每次事件最多发送 8 包；Opus 直接写入发送包；退出或断连清理旧上行 |
| 持续通话错误处理在主任务睡眠重连，弱网可能频繁连接 | 非阻塞截止时间重连，2 秒起步、最多 60 秒退避，离线暂停，挂断取消 |
| WebSocket 短包、错误 payload 长度、非 NUL 结尾 JSON、错误 hello 字段导致越界或无效配置 | 有界解析，验证完整头和负载，不修改收到的缓冲，校验握手参数并回收失败连接 |
| MQTT hello 的 UDP 参数、密钥和 nonce 未校验，UDP 连接失败仍通知成功 | 完整校验后再建立通道，检查连接结果，校验 UDP 长度和重复序号 |
| MQTT 首次连接失败或重试时忙碌后不再重试 | 统一按 60～600 秒退避重排，成功后取消并重置，已销毁实例的迟到任务安全跳过 |

## 追加修复：启动后立即进入 AI 相机的文字缺字

用户实机反馈进入相机后文字乱码。当前板启动字体 `font_noto_basic_20_4` 不包含“按键拍照 / 双击返回”的汉字。相机标签在 `lv_layer_top()` 上显式绑定了启动字体；后台资源加载后的 `LcdDisplay::SetTheme` 只更新主界面，相机标签继续使用缺字的字体。

- 本板显示类在应用主题后同步相机提示字体，实时预览、停留照片和错误提示均可更新，无须退出重进。
- 相机读取显示类在 LVGL 锁内维护的字体快照，避免页面创建时直接读取资源任务正在替换的主题字体成员。
- 标签持有动态字体的共享所有权，替换样式和删除标签完成后才释放旧字体。
- 用真实 Unicode 字形查询检测缺字；资源字体未就绪时使用内置英文字体显示对应操作提示，加载完成后恢复保存的中文提示或识图结果。检查仅在提示或字体改变时进行，不进入每帧预览路径。
- 此次修改已通过目标固件构建（应用 `0x2da0c0` 字节，分区剩余 28%）。字体回归脚本 `scripts/tests/test_camera_font.py` 使用真实 LVGL 字形查询、UTF-8 解码、启动字库和 Montserrat 字库；UI 操作及完整中文字库替换用 stub 验证。
- 字体回归通过，ASan / UBSan 无错误；覆盖字体尚未应用时创建页面、全部备用提示字形、中文恢复、识图结果保留、重复主题应用和字体销毁顺序。
- 追加修复准备烧录时，电脑已检测不到原 COM21 / COM20，串口枚举为空。新固件尚未写入设备；待板子重新连接后烧录，并复测刚启动进入相机的屏幕效果。

## 已暂停：P1 / ML307 WebSocket 心跳回调阻塞

用户随后决定暂不使用 ML307。当前 `lichuang-dev-ml307` 保留硬件型号与引脚，网络基类改用 `WifiBoard`，启动直接连接 WiFi，忽略旧的 `network/type` 选择，不创建 ML307 板实例。启动双击入口改为 WiFi 配网，配网期间双击保持当前页面。ML307 心跳缺陷作为后续重新启用蜂窝网络时的待办。

WiFi 配网事件会移除主页或相机覆盖层，让热点和配网提示可见；联网后恢复主页。已有 WiFi 凭据继续使用，共用的 TCP、SSL、HTTP 和 WebSocket 网络组件继续保留。

`managed_components/78__esp-ml307/src/web_socket.cc` 收到 Ping 后，在接收回调中同步发送 Pong。ML307 这条回调由 `AtUart::EventTask` 执行，而 `Ml307Tcp::Send` 等待的 AT 响应也由该任务解析；因此会自等到超时，发送锁竞争还会放大停顿。应用层收到 `OnData` 前已发生控制帧处理，应用重连退避无法消除此问题。

本轮保留该明确风险，未修改会被组件管理器覆盖的依赖缓存。后续应采用可持久化的组件补丁或本地组件覆盖：将 Ping 载荷投递到可取消的发送任务或应用任务，在验证连接代次后发送 Pong，并处理断连和析构时的回调生命周期。需用 ML307 实机跨多个心跳周期验证；仅通过 WiFi 或普通音频回归无法证明该问题消失。
